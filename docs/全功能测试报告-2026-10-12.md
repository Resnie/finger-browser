## 已确认的问题

### F01：余额页请求返回 401 后仍保留登录会话（P2）

复现：登录 → 余额与账单 → summary 返回 HTTP 401。页面显示请求失败，但没有“去登录”提示，不清除 token，不回到登录页。期望静默错误提示不影响统一认证失效处理。

原因：`src/api/billing.js` 为两条请求设置 `silentError: true`；`src/utils/request.js:106` 和 `:152` 将业务 code 401、HTTP 401 的处理都放在 `!silentError` 分支内。

证据：[主操作结果第 39 组](test-evidence/2026-10-12/ui-main.json)、[失败界面](test-evidence/2026-10-12/silent-401.png)。本次直接 UI 复现的是 HTTP 401；业务 code 401 同样跳过处理的结论来自源码检查。

### F02：浏览器“未分组”单元格和按钮没有文字（P2）

复现：创建窗口 → 批量改到某组 → 批量改到未分组。服务端 group_id=0 已保存，但分组单元格为空，无法通过可辨识的“未分组”入口再次单条修改分组。Windows 也观察到同样空白。

原因：`src/views/browser/tablePane.vue:17` 直接输出 `scope.row.group`，没有未分组 fallback。

证据：[主操作结果第 22 组](test-evidence/2026-10-12/ui-main.json)、[空白分组截图](test-evidence/2026-10-12/browser-ungrouped.png)。不将成功的 API 批量移组误报为后端保存失败。

### F03：全局“重启安装”入口没有捕获安装 Promise 失败（P2）

复现：发出受控 update-downloaded 事件 → 在全局弹框确认重启安装 → install-update IPC 拒绝。产生未捕获的渲染错误，用户没有收到可恢复的安装失败状态。设置面板自身的安装入口会正确捕获同样失败。

原因：`src/App.vue:28` 调用 `window.ipcRenderer.installUpdate()` 没有 `await`，外层 `try/catch` 无法捕获异步拒绝。

证据：[补充结果第 6 组及最终异常断言](test-evidence/2026-10-12/ui-edge.json)、[界面](test-evidence/2026-10-12/global-update-install.png)。测试错误 `test-global-install-failed` 为人为注入；证实异常处理缺陷，不等同于真实更新包已下载和安装失败。

### F04：启动时在线内核列表加载失败，恢复网络后“刷新版本”仍为空（P2）

Windows 实机复现：客户端启动时本地测试 API 不可用 → 列表为空 → 恢复服务并确认 /health 正常、服务端有 140/144 → 点击刷新仍为空 → 打开现有窗口提示请求版本不存在 → 退出并重新启动后版本出现。

原因：`electron/main/browserCoreManager.js:29` 的 get-all-browser-versions 只读取 store；`BrowserKernelManager.vue` 刷新按钮调用该 IPC，没有重新请求服务端。

影响：暂时断网后用户不能通过页面恢复，需要重启客户端。此问题不等同于 Windows 不支持 140 内核。

### F05：Windows 操作列与弹窗底部裁切（P2）

在远程实机默认缩放下，浏览器表格操作列位于右侧视口外；横向拖动滚动条后可到达打开、编辑、克隆和更多，但删除按钮仍有文字被右边界裁切。缩小应用显示后仍观察到末尾裁切。`tablePane.vue` 操作列 min-width=260 且按钮 flex-nowrap。

这是布局与操作发现性问题；已经通过横向滚动到达打开按钮，不声称操作列完全不可用。最小窗口测试此前仅验证 body 不溢出，不能据此判定所有操作按钮完整可见。

实机补充：默认缩放下克隆弹窗滚到内容底部，提交按钮仍位于视口下方；在应用菜单继续缩小两级后才到达“创建副本”。需要约束弹窗总高度并保持 footer 可见；仅将内部表单设为可滚动不够。

### F06：Windows 已保存窗口恢复失败，新窗口首次启动正常（P1）

实机对照：Mac 保存的测试窗口在 Windows 内核 140.0.7259.2 上恢复时，进程启动成功、会话存储恢复完成，但创建业务标签失败。日志为 `browserContext.newPage: Protocol error (Target.createTarget): Failed to open a new tab`，随后清理进程。退出并重新启动客户端后仍复现。

使用同样配置克隆一个不带恢复 state 的新窗口，首次启动成功，实际页面验证 Win32、en-US、Asia/Singapore、1366×768、4 CPU、8GB、DNT=1；关闭保存后再开该副本也失败。因此不能仅归因于 Mac 原生档案格式，也不能判定 Windows 浏览器运行态通过。直接从独立全新目录启动相同内核可显示网页，排除了内核文件损坏或完全不能运行。

副本重开在 2026-10-12 15:57:33 UTC 的日志中记录 `browserContext.newPage: Target page, context or browser has been closed`；原窗口失败为 15:48:49 UTC 的 Target.createTarget 错误。两个场景均在恢复后创建页面阶段失败。

源码线索：`BrowserInstance.restoreOriginStorageForPersistentContext` 创建恢复临时页并关闭现有页，finally 又关闭临时页；`restoreStartupPages` 随后尝试创建恢复页。Windows 有窗口模式下最后一个窗口关闭后的生命周期值得优先修正和回归。**失败行为已证实；上述根因属于源码与日志推断，尚未以修复后的实机回归最终确认。**

## 外部依赖失败与未完成场景

1. **macOS 自动更新渠道失败**：当前打包客户端实际请求 `https://github.com/Resnie/finger-browser/releases/download/0.2.0/latest-mac.yml`，返回 404。Windows 同版本元数据检查正常；不能由此推断 Mac 更新也正常。
2. **默认邮件 TLS 失败**：只读 readiness 检查报告 API 主机名不匹配 `ERR_TLS_CERT_ALTNAME_INVALID`，IMAP/POP3 为 `CERT_HAS_EXPIRED`；邮箱创建配置未启用，API 未配置 HTTPS。本轮没有忽略证书错误。历史验收中的证书例外成功不算本轮默认配置通过。
3. **正式新版本自动更新未完整验收**：没有发布高于 0.2.0 的正式测试版本。本轮覆盖了真实同版本检查和覆盖安装，以及受控更新事件/失败分支；不声称已验证真实新版本下载、签名校验、自动重启安装和升级后回归。
4. **安装生命周期范围**：Windows 同版本覆盖安装已执行；全新空系统首装、卸载后重装、跨版本升级/降级和真实下载损坏后的安装回滚没有全部执行。现有测试客户端需要保留，不以卸载现有测试环境替代一次性空系统验收。
5. **真实网站与设备边界**：指纹测试覆盖页面主线程；未穷举 Worker/OffscreenCanvas、所有公网 WebRTC/STUN/TURN、字体完整渲染隔离、每个网站反检测和硬件组合。OS 加密的 Chromium 密码库、设备私钥、原生扩展组件、任意下载文件不在已验证便携恢复范围。
6. **预留功能**：链上充值和月套餐当前未开放，验证的是入口说明和不可操作状态，不能称为充值/套餐功能已实现。
